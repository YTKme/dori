# Schema

All application tables are prefixed `dori_`; identity/tenancy tables
(managed by better-auth) are prefixed `betterauth_`.

## Base columns

Every tenant-scoped CRM table embeds a common set of columns (see
[`src/_drizzle/column.ts`](../src/_drizzle/column.ts)):

| Column | Type | Notes |
|---|---|---|
| `id` | uuid | Primary key, `uuidv7()` (time-ordered) |
| `organizationId` | uuid | Tenant key → `betterauth_organization.id` (cascade) |
| `ownerId` | uuid | Record owner → `betterauth_user.id` |
| `createdById`, `updatedById` | uuid | Audit → `betterauth_user.id` |
| `createdAt`, `updatedAt` | timestamptz | Auto-managed |
| `deletedAt` | timestamptz | Soft delete (null = active) |

## Identity & tenancy (better-auth)

`user`, `session`, `account` (OAuth/credentials), `verification`,
`organization`, `member`, `invitation`, `team`, `team_member`.
Record identifiers are UUID v7 generated by PostgreSQL
(`advanced.database.generateId = false`).

## CRM entities

**Sales**
- `account` — company/customer. Self-referential (`parentAccountId`),
  billing & shipping addresses.
- `contact` — person, optionally linked to an account; self-referential
  (`reportsToId`).
- `lead` — unqualified prospect; converts to account + contact (+ opportunity).
- `opportunity` — deal linked to an account and a stage.
- `opportunity_stage` — per-organization pipeline stage (ordered, probability,
  won/closed flags). Seeded automatically for every new organization.
- `opportunity_contact_role` — contacts on an opportunity.

**Products / CPQ**
- `product`, `price_book`, `price_book_entry`,
  `opportunity_line_item`, `quote`, `quote_line_item`.

**Service** — `case`, `case_comment`.

**Marketing** — `campaign`, `campaign_member`.

**Engagement** — `activity` (task/call/meeting/email) and `note`, each related
to parent records via typed nullable foreign keys (preserving referential
integrity).

**API** — `personal_access_token` (SHA-256 hashed; org-scoped).

## Picklists

Enumerated fields (statuses, ratings, sources, types, …) are stored as text and
validated by Zod enums defined in [`src/type/enum.ts`](../src/type/enum.ts).

## Relations

Relations for the query API are declared centrally in
[`src/_drizzle/relation.ts`](../src/_drizzle/relation.ts) (Drizzle relations v2).

See [`entity.mermaid`](entity.mermaid) for a diagram.
